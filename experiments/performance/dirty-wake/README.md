# Queued content-wake experiment

This rejected candidate gave X11 a coalesced foreground wake for changed content, separate from the display timer and animation callback queue. It preserved visibility, weak-window lifetime, recovery, reentrancy, pending presentation and frame-rate policy. Pinned core and Linux source copies came from checksum-verified archives and reviewed patches. Existing platform request structures stayed unchanged. The patch records the candidate and its preparer; this folder does not apply it.

Four loaded Codex runs used one ordinary release, with the wake off, on, on, then off. Pixel-identical idle coalescing stayed enabled in both arms. All 48 characters, 2,441 frames, 80 worker completions, source custody and exact owner restoration passed independent review. The candidate failed all frozen progression criteria. Enabled median upper bounds were 92.896 and 86.003 ms against paired controls 92.074 and 78.278 ms. The combined maximum upper bound was 160.070 ms against 156.974 ms. UI-thread CPU was also higher in the enabled observations. Wide capture intervals remain part of these bounds; they are not exact application stalls.

The candidate is not selected. Its core/Linux patches, preparer, lock and owning documentation changes were removed from active product source after verification. Older and experimental cache directories, exact artifacts, failed attempts and private evidence remain preserved. The native fixture retains explicit flag support so the frozen experiment can be reproduced. No Herdr parity, native animation fidelity or foundation acceptance follows from this result.

The next bounded question is sustained terminal-output fairness. A self-waking task can be polled again while Linux is still draining the same foreground dispatch. That is a reachable scheduling risk, not a reproduced stall. The CPU-only idle-Codex tests did not reproduce the reported multi-second symptom. Keep real input, produced and consumed work, source observations and cleanup evidence distinct. Private records remain under /var/tmp/voyager-typing-latency-20261108/ outside Git.
