# VoyagerShell agent guide

Shared product instructions for review. They are not automatically loaded by VoyagerShell. Read [the exposure proposal](../proposal.md) for integration status. Main retains the Electron reference; native-foundation observations describe a separate candidate. The running build's capabilities and generated contracts remain authoritative.

## Explain the workspace

VoyagerShell is a configurable workspace for people and agents. In the selected workspace model, a Voyage is a space, a Fleet is a tab, a Vessel places content within a Fleet, and a Portal is intended to place content across a Voyage. Verify actual placement scope on the installed build; legacy storage names do not establish Voyage-wide behavior. A content type can be an agent terminal, Notes or another view supported by the installed runtime. Discover the available types; do not assume any program can embed its interface.

The astronaut represents the user's authority. Its dock chooses explicit workspace context. Overwatch names whole-workspace focus in the current native UX. Keyboard focus, visual selection, a program's working directory and delegated work are separate. The separate native candidate captures focus and revision when accepting a human request. Main's retained Electron reference currently uses live/newest dock focus instead. Check the running build before assuming later docking cannot retarget an in-flight request.

Herdr Core runs programs and retains their terminal identity. Voyager owns the workspace, content placement and application policy. Closing a viewer, hiding a Vessel, moving it or removing a package is different from stopping its program. Inspect real IDs and actual outcomes. An accepted request is not a completed effect. Report Applied, Rejected and Uncertain outcomes accurately; do not replay uncertain operations or automatically restore agents.

## Help a new user

Answer with the installed version's actual controls and capabilities. Explain Voyage, Fleet, Vessel, Portal and docking through the user's current task. Check available content and commands when needed. Give a short actionable step, then verify the requested result. Identify unavailable features plainly instead of describing a roadmap as working software.

For content state, use the supported application operations and expected revisions. Do not bypass the content writer by changing its persisted files. Follow the user's actual project instructions for project work. Workspace membership, documentation and a role stated in a payload do not grant permission.

## Author an animation

Read [the animation-authoring guide](animation-authoring.md) and its example manifest. Produce PNG drawings plus a versioned JSON pack. Configure named poses, source rectangles, alignment, timing and supported effect parameters. Preview through the existing player, including errors and reduced motion. Whole-image fades do not invent natural movement. Present the result for visual review. The current local preview cannot install an animation in the native app.

## Customize a Vessel or Portal

Read [the content-authoring guide](content-authoring.md), the available installed content catalogue, the selected package's guide and generated declarations. If discovery is not exposed, report that limit instead of inventing a catalogue command. Inspect actual package files and the supported renderer first. The native foundation uses JavaScript/TypeScript to compose supported GPUI components. It does not provide browser HTML/CSS/DOM/WebGL automatically. The retained Electron implementation uses a different content host; its examples cannot be copied blindly into native packages.

Keep the content instance, placement and optional Core backend separate. Native source authoring must use current package manifests and registered interfaces. Discover which types are available. Adding an arbitrary new type is not established merely by creating files. Keep original personal source and data; verify a good live edit, a broken edit retaining the last usable version, and reversible removal. Do not stop a backend to reload or hide a view.

## Discover detail only when needed

Load the animation-authoring or content-authoring guide for that task. Read generated definitions for exact argument and result shapes. Refresh capabilities and live state through the installed application. The guide is documentation, not an authorization token or a copy of live workspace state.

The private assistant's administrator policy is supplied separately by Voyager. It inspects, arranges and delegates through its bound tools. Working Vessel agents perform project and extension-source work within their own permissions. This common guide must not grant a worker the private assistant's owner authority, private conversation access or wider tools.
