# Feature map

Generated from `tests/native/features.toml`, `architecture/atlas-features.yaml`, the declared invariants in `tests/native/declared-invariants.toml` and the context owners in `tests/architecture/vocabulary.yaml` by `npm run features:generate`. Edit those inputs, then regenerate. The complete map with code paths and state is `architecture/features.yaml`. For each feature it lists the declared invariants that name the feature, and for each invariant its guards, checks, formal properties and the journeys its checks run.

The feature map ties each feature of the app to its source files, its declared invariants and the journeys that prove it. A journey is a test that drives the real app.

The `proof` column says how a feature is proven. It is `native` when a native journey covers the feature, and `python-only` when only a retained Python journey does. It is `tests` when the feature has no journey and a CI step named in `architecture/atlas-features.yaml` is its proof. Such a feature is shown as proven by its tests. Only a feature with no journey may take such a step.

## The change gate

On a pull request, `npm run features:check -- --base <base>` fails when a change touches a feature's source paths with no change to its map entry and no recorded run. Record the run by adding a line `Journeys run: <journey>, <journey>` to the PR description, then push a new commit, because editing the description does not rerun CI. Every such line counts. A feature needs all of its native journeys, or one Python journey when it has no native journey. Another way through is to change the feature's entry in `tests/native/features.toml` and run `npm run features:generate`. A change to a declared invariant alone does not count, because the gate compares each entry without its invariants. A feature proven by its tests needs no record, because that CI step runs on the same pull request.
